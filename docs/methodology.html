Data documentation

Source, scope, and verification

The project never substitutes generated, estimated, or manually keyed baseball data. If MLB does not return a value, the interface shows it as unavailable. The raw download is the unmodified official response.

One authoritative source

Schedule and game data come directly from the MLB Stats API on the MLB-controlled statsapi.mlb.com domain over HTTPS. The site makes these requests in the visitor’s browser:

GET https://statsapi.mlb.com/api/v1/schedule
    ?sportId=1
    &date=YYYY-MM-DD
    &gameTypes=R,F,D,L,W
    &hydrate=linescore

GET https://statsapi.mlb.com/api/v1.1/game/{gamePk}/feed/live

The full game feed contains MLB’s game metadata, teams, venue, status, players, linescore, box score, decisions, play-by-play, pitch/action events, runners, and available tracking measurements. Every request includes a link to its exact official endpoint.

Archive scope

  • League: Major League Baseball (sportId=1).
  • Start: January 1, 2014. Dates before the first regular-season game simply return no qualifying game.
  • End: the date on which the browser or archive command runs.
  • Included types: regular season (R) and MLB postseason game-type codes F, D, L, and W.
  • Excluded: Spring Training, exhibitions, and the All-Star Game.

The web viewer requests any date on demand, so it does not depend on a hand-maintained list of games. The repository’s command-line archiver enumerates games from the same official schedule endpoint and supports resumable full-history pulls.

Verification rules

A response is displayed or written only after all applicable checks pass:

  1. The request URL uses HTTPS and the exact host statsapi.mlb.com.
  2. The HTTP response succeeds and parses as JSON.
  3. The response includes MLB Advanced Media’s copyright notice.
  4. For a game feed, the returned gamePk equals the requested identifier.
  5. The archiver records a SHA-256 digest of every exact raw response in its manifest.

These checks establish provenance and detect mix-ups or later file corruption. They do not alter MLB’s data. MLB can revise a completed game; rerunning with --refresh retrieves and fingerprints the revised response.

What each download means

Raw JSON

The complete MLB response serialized as readable JSON. No fields are renamed, corrected, inferred, or dropped. Use this when exact source fidelity matters.

Plain text report

A deterministic presentation of official fields: provenance, game metadata, line score, decisions, every at-bat description, every pitch/action event, runner movements, and batting/pitching lines. Labels and layout are added by this project; baseball values and descriptions come from MLB.

Events NDJSON

Newline-delimited JSON for streaming tools. Each line identifies itself as metadata, a play, or an event and retains the associated gamePk and array indexes. The raw JSON remains the canonical no-loss copy.

Known limitations, stated rather than filled in

  • Availability and field coverage vary by season, game state, park, and MLB’s own collection systems.
  • Older games can contain less pitch or tracking detail than newer games.
  • Postponed, suspended, cancelled, or not-yet-started games may have no plays.
  • The official feed can be corrected after a game. The retrieval timestamp and digest identify the version downloaded.
  • This project does not promise that MLB’s public endpoint will remain unchanged or continuously available.

Live event log (local only)

The web viewer includes an Event log tab that records short-lived official-game states as this page observes them during a Live game: a run scoring, an official-scorer ruling that is initially pending and later finalized, a scoring ruling corrected after the fact, and a home-run / boundary call that goes under replay review. Each event is captured at every stage seen — for example, pending then resolved, or under review then overturned / confirmed.

This log is a local-only record of what the page watched unfold. It is stored in the visitor’s browser (localStorage, keyed to the game) so it survives a refresh and can be reopened later; it is not part of MLB’s official payload and is never written to this repository or any server. Ingestion runs only while the game’s abstractGameState is Live, so a game that was never opened while Live produces no entries. The baseball values shown are the literal fields MLB returned (liveData.plays.scoringPlays, result.eventType, playEvents[].details.eventType, playEvents[].reviewDetails, and gameData.status.reason); only the human-readable labels are derived by this project.
